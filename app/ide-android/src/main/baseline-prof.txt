# Baseline profile for the installed IDE app (com.sagirhossendhali1999-cyber.code).
#
# AGP compiles this file into assets/dexopt/baseline.prof. At install time the package manager AOT-compiles
# the matched methods (dex2oat) instead of interpreting and JIT-compiling them on first use. Play installs
# apply the profile directly; sideloaded installs apply it through androidx.profileinstaller on first launch.
#
# Rules use the human-readable profile format with wildcards, expanded by profgen against the APK dex:
#   HSPL<class>->**(**)**   every method of the matched classes is Hot, Startup and Post-startup
#   L<class>                the matched classes are loaded and initialized at startup
#   *                       matches within one package segment, ** matches across segments
#
# Scope: the IDE's own startup, editing and analysis paths, plus targeted third-party parser and tree builder
# classes. Whole third-party trees (the IntelliJ platform, the Kotlin compiler, JDT) are deliberately left
# out: compiling all of them bloats the odex, which costs more than it saves on low-storage devices.
# AndroidX and Compose libraries ship their own baseline profiles, which AGP merges in automatically.
